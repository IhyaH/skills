# TJC 联调排障

## 屏不响应 MCU 指令

优先检查：

1. 是否每条命令都追加了 `FF FF FF`
2. MCU_TX 是否接屏_RX，MCU_RX 是否接屏_TX
3. 是否共地
4. 是否误用了带板载 USB 转串口芯片占用的 USART
5. 是否在屏未启动完成前就发指令

文档相关事实：

- 官方明确指出启动成功后会发送 `0x88 + 结束符`
- 用户若要求严格等待启动，可让 MCU 先等 `0x88`

## MCU 能发，收不到屏返回

优先检查：

1. 屏 TX 到 MCU RX 的线路和电平
2. 是否是 `X3/X5 -> 3.3V MCU` 组合
3. MCU 侧是否正确解析了 `FF FF FF` 帧尾
4. 是否期待了受 `bkcmd` 影响的返回，而实际已设置 `bkcmd=0`

文档相关事实：

- 官方明确提到部分 `3.3V` 单片机接 `X3/X5` 可能收不到，可尝试串 `1K` 电阻

## `get` 返回异常

检查：

1. 读的是 `txt` 还是 `val`
2. 是否按 `0x70` / `0x71` 分别解析
3. `0x71` 是否按 4 字节小端解析
4. 控件名和属性名是否写对

## 中文乱码

检查：

1. 工程编码是 `GB2312` 还是 `UTF-8`
2. MCU 发送字节编码是否与工程一致
3. `txt_maxl` 是否足够
4. 字库是否正确导入

## 页面跳转后数据丢失

检查：

1. 相关控件或变量的 `vscope` 是否为全局
2. 是否把仅当前页面有效的行为拿去跨页面使用

文档相关事实：

- 在“跨页面赋值/跨页面操作变量”的官方说明页中明确写到：
  - `click/vis/tsw` 无法跨页面触发控件
  - 定时器控件只能在当前页面运行
  - 曲线波形控件只能在当前页面添加数据点

## 波形不显示

检查：

1. 是否在当前页面给波形加点
2. 是否连续加了足够的数据点
3. 通道号和数据范围是否合理

## 串口缓冲区溢出

检查：

1. 是否连续发送过快
2. 是否发送了超长文本
3. 是否根据系列差异保守处理缓冲区

文档相关事实：

- 设备会返回 `0x24 + 结束符`
- 系列缓冲区大小存在差异

## `sendme` 使用后与原有协议冲突

文档相关事实：

- 官方明确不建议直接使用 `sendme`
- 可用：

```text
printh 66
prints dp,1
printh ff ff ff
```

来替代 `sendme`，从而自定义发送格式

## 透传模式卡住

检查：

1. 是否等到 `0xFE + 结束符` 才开始透传
2. 是否在完成后收到 `0xFD + 结束符`
3. 是否误把透传数据继续按字符串命令发送
4. 是否需要按文档规定的强制结束包来中止透传
