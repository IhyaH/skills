# TJC 串口协议参考

## 基础规则

- MCU 发给屏的标准指令是 ASCII 文本加结束符 `0xFF 0xFF 0xFF`。
- 屏返回给 MCU 的标准数据帧也以 `0xFF 0xFF 0xFF` 结束。
- 帧边界的主依据是三个连续 `0xFF`。

## 常用 MCU -> 屏指令

### 页面跳转

```text
page main
page 2
dp=2
```

说明：

- 推荐 `page 页面名`，可读性更高。
- HMI 侧 `page` 之后的语句不会继续执行。

### 触发控件事件

```text
click b0,1
click b0,0
```

说明：

- `1` 表示按下事件，`0` 表示弹起事件。

### 获取属性

```text
get n0.val
get t0.txt
```

说明：

- `get n0.val` 期望返回 `0x71` 数值帧。
- `get t0.txt` 期望返回 `0x70` 字符串帧。

### 控件可见与触摸

```text
vis b0,0
vis b0,1
tsw b0,0
tsw b0,1
ref t0
```

### 直接赋值

```text
n0.val=100
t0.txt="hello"
```

说明：

- 文本赋值时字符串内容必须和工程编码一致。

## 屏 -> MCU 返回帧

### `bkcmd` 非 0 时的执行结果

默认上电 `bkcmd=2`，即仅在执行出错时返回错误码。

| 返回码 | 含义 |
| --- | --- |
| `0x00` | 无效指令 |
| `0x01` | 指令成功执行 |
| `0x02` | 控件 ID 无效 |
| `0x03` | 页面 ID 无效 |
| `0x04` | 图片 ID 无效 |
| `0x05` | 字库 ID 无效 |
| `0x06` | 文件操作失败 |
| `0x09` | CRC 校验失败 |
| `0x11` | 波特率设置无效 |
| `0x12` | 曲线控件 ID 或通道号无效 |
| `0x1A` | 变量名称无效 |
| `0x1B` | 变量运算无效 |
| `0x1C` | 赋值操作失败 |
| `0x1D` | 掉电存储空间操作失败 |
| `0x1E` | 参数数量无效 |
| `0x1F` | IO 操作失败 |
| `0x20` | 转义字符使用错误 |
| `0x23` | 变量名称太长 |

### 不受 `bkcmd` 影响的返回帧

| 帧头 | 含义 | 当前可确认内容 |
| --- | --- | --- |
| `0x24` | 串口缓冲区溢出 | 无数据或附加字段未在本次提取中确认 |
| `0x65` | 控件点击事件 | 文档示例确认格式为 `page_id + ctrl_id + event`，示例显示这三个字段各占 1 字节 |
| `0x66` | 当前页面 ID | 一般可按 1 字节页号处理 |
| `0x67` | 触摸坐标数据 | 格式：`0x67 + X坐标高位 + X坐标低位 + Y坐标高位 + Y坐标低位 + 触摸事件状态 + 结束符`（总计 9 字节）。需先设 `sendxy=1` 才会产生 |
| `0x68` | 睡眠模式触摸事件 | 格式与 `0x67` 相同（9 字节），仅在睡眠状态下触发 |
| `0x70` | 字符串变量数据返回 | 帧头后为原始字符串字节 |
| `0x71` | 数值变量数据返回 | 帧头后 4 字节小端整数 |
| `0x86` | 自动进入睡眠模式 | 事件通知 |
| `0x87` | 自动唤醒 | 事件通知 |
| `0x88` | 系统启动成功 | 常用于在线检测屏是否存在 |
| `0x89` | 开始 SD 卡升级 | 后续交互未在本次提取中确认 |
| `0xFD` | 透传数据完成 | 细节待核实 |
| `0xFE` | 数据透传就绪 | 细节待核实 |

## 解析建议

- 先读取完整帧，再根据帧头分支解析。
- `0x71` 固定按 4 字节小端解析。
- `0x70` 的字节序列长度由帧尾位置决定。
- `0x65` 可按文档示例解析为 `page_id + ctrl_id + event`。
- `0x67` 和 `0x68` 在官方文档中均定义为 9 字节帧（`XH + XL + YH + YL + event`），代码中可以按此格式实现解析。

## 编码

- 数字、英文字母、符号遵循 ASCII。
- 中文必须与屏幕工程编码一致：
  - `GB2312`：通常每个汉字 2 字节
  - `UTF-8`：通常每个汉字 3 字节

## 缓冲区与节流

- MCU 侧建议使用约 `1KB` 环形缓冲区。
- 文档建议中断接收、主循环解析。
- 对于发送频率较高的项目，保守起见在连续指令间留出适当间隔，避免屏端缓冲区溢出。
