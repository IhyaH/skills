# TJC 常用系统变量

这里只保留当前离线官方文档材料中明确出现、且对 MCU/HMI 联动最常用的变量。

## `bkcmd`

- 作用：串口指令执行状态返回控制
- 官方默认：上电后 `bkcmd=2`
- 文档明确：
  - `bkcmd=0` 不返回执行结果
  - `bkcmd=1` 仅返回成功的结果
  - `bkcmd=2` 仅返回失败的结果（上电默认）
  - `bkcmd=3` 成功或失败皆返回结果
  - 某些返回帧不受 `bkcmd` 影响，如 `0x65`、`0x66`、`0x67`、`0x68`、`0x70`、`0x71`、`0x86`、`0x87`、`0x88`、`0x89`、`0xFD`、`0xFE`、`0x24`

## `dp`

- 作用：当前页面 ID
- 文档示例：
  - `dp=2` 可跳转页面
  - `prints dp,1` 可配合 `printh 66` 和 `printh ff ff ff` 模拟 `sendme`
- 建议：
  - 如果需要严格自定义页号返回格式，优先用 `printh + prints dp,1` 组合，而不是直接 `sendme`

## `dim`

- 作用：亮度相关变量
- 文档在滑块/亮度场景里反复使用
- 生成代码时：
  - 适合用作滑块实时调亮度
  - 不要在未确认场景下把它与掉电保存变量混用

## `dims`

- 当前材料里主要以“不要高频写带保存的亮度变量”这一类经验出现
- 若生成频繁刷新亮度的逻辑，优先使用 `dim`

## `bauds`

- 文档明确可在 `program.s` 中配置波特率
- 当前材料没有给出“MCU 运行中通过标准串口命令改波特率”的完整安全流程
- 因此：
  - 可以在说明中提到 `program.s` 可配置波特率
  - 不要默认生成运行中切波特率的 MCU 驱动代码

## `sleep`

- 睡眠相关变量在常见问题和返回帧中出现
- 文档材料显示：
  - 睡眠状态下，只有少量指令仍可执行，如 `get`、`prints`、`printh`，以及部分睡眠相关赋值语句

## `wup`

- 睡眠唤醒相关变量在常见问题材料中出现
- 当前 skill 只把它作为“睡眠相关系统变量”记录，不扩展未明确的位定义或取值范围

## 生成代码时的规则

1. 变量名必须按文档原样使用，注意大小写。
2. 不能把系统变量当成普通控件属性来解释。
3. 如果变量的取值范围或行为没在当前文档中明确，不要编造详细语义。
